---
title: Install Herdsman
description: Install, update, and verify Herdsman on Linux, macOS, and Windows.
---

Herdsman publishes release binaries for Linux, macOS, and Windows. Windows has platform-specific limitations; see [Windows support](/docs/windows-beta/).

## Install

On Linux or macOS, run:

```bash
curl -fsSL https://remziduzagac.github.io/herdsman/install.sh | sh
```

On Windows, run:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://remziduzagac.github.io/herdsman/install.ps1 | iex"
```

If endpoint security blocks that fileless PowerShell command, open Command Prompt and run:

```cmd
curl.exe -fsSLo install.cmd https://remziduzagac.github.io/herdsman/install.cmd && install.cmd && del install.cmd
```

The installer downloads the release binary for your platform, checks its checksum, and places it on your PATH. On Windows, PATH points to the active versioned release directory; the installer also updates the `current` and stable `bin` compatibility aliases, so updates do not need to overwrite a running `herdsman.exe`.

## Install with Homebrew

If you already use Homebrew, on macOS or Linux, install from herdsman's tap:

```bash
brew install remziduzagac/tap/herdsman
```

Update it with `brew upgrade herdsman`.

## Install with mise

If you already use mise, install the release binary straight from GitHub:

```bash
mise use -g github:remziduzagac/herdsman
```

mise holds back releases younger than a day, so a new release shows up in mise the day after it is published. To take one right away, ask for its version, such as `mise use -g github:remziduzagac/herdsman@1.0.0`.

## Install with Nix

If you already use Nix, Herdsman provides a flake that builds Herdsman from source:

```bash
nix run github:remziduzagac/herdsman/v1.0.0
nix build github:remziduzagac/herdsman/v1.0.0
nix profile install github:remziduzagac/herdsman/v1.0.0
```

Replace `v1.0.0` with the latest release tag. You can omit the tag to track `main`, but release tags are recommended for normal installs.

The flake also exposes a development shell:

```bash
nix develop github:remziduzagac/herdsman
```

Use the same Nix workflow to update Herdsman. For a profile install, list your profile entries and upgrade the Herdsman entry:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

If Herdsman is an input in your own flake, update that input and rebuild your system, Home Manager, or development environment:

```bash
nix flake update herdsman
```

## Download manually

You can also download a binary from [GitHub releases](https://github.com/remziduzagac/herdsman/releases).

Choose the asset that matches your system:

| System | Asset |
| --- | --- |
| Linux x86_64 | `herdsman-linux-x86_64` |
| Linux aarch64 | `herdsman-linux-aarch64` |
| macOS Intel | `herdsman-macos-x86_64` |
| macOS Apple silicon | `herdsman-macos-aarch64` |
| Windows x86_64 | `herdsman-windows-x86_64.zip` |

On Linux or macOS, make it executable and move it somewhere on your PATH.

```bash
chmod +x herdsman-linux-x86_64
mv herdsman-linux-x86_64 ~/.local/bin/herdsman
```

### Windows archive

Every release includes `herdsman-windows-x86_64.zip`. The archive contains `herdsman.exe` and its app-local ConPTY runtime. Keep the extracted directory together; do not copy only `herdsman.exe`.

## Verify

Start Herdsman:

```bash
herdsman
```

If your shell cannot find `herdsman`, restart the terminal or check that the install directory is on your PATH.

## Update

Herdsman checks for new releases and notifies you in the app. You can update manually:

```bash
herdsman update
```

Use `herdsman update` only for installs managed by Herdsman's own installer. Update Homebrew, mise, and Nix installs through those package managers instead.

By default, `herdsman update` installs the new binary and leaves endpoint-generation-1 servers and their pane processes running. Start Herdsman again to reconnect with the updated client. Client-only changes work immediately. A new server-side action stays unavailable until that server is updated and restarted; the client shows a notice instead of disconnecting. Servers from before endpoint generation 1 need one final stop during update.

When it finishes, `herdsman update` lists any running server still on the old version with the command that restarts it, and your saved SSH machines, which run their own Herdsman. Run `herdsman update` on each machine to update it too.

To opt into experimental live server handoff for supported running sessions, run:

```bash
herdsman update --handoff
```

When both servers support agent-status transfer, live handoff preserves hook-reported agent status until the next report arrives. Handoff from an older server can temporarily show a running agent as idle.

Live handoff does not apply to Homebrew, mise, or Nix package-manager updates. For those installs, update with the package manager, then run Herdsman again to reconnect with the updated client. The compatible old server keeps running. Restart it later with `herdsman server stop` or `herdsman session stop <name>` only when you want server-side changes from the new release.

## Requirements

Release binaries are available for Linux and macOS on x86_64 and aarch64, and for Windows x86_64. See [Windows support](/docs/windows-beta/) for supported workflows and known limitations. Windows ARM64 runs the x86_64 build under Windows emulation.
