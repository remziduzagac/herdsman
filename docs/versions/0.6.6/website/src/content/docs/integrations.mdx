Herdsman detects supported agents automatically. Integrations make that detection more precise by reporting semantic state directly to Herdsman.

Use integrations when you want reliable `working`, `blocked`, `idle`, and `done` state from agent hooks or plugins.

## Install integrations

Open settings inside Herdsman and use the integrations tab to install recommended integrations for agents found on your `PATH`, or run commands manually:

```bash
herdsman integration install pi
herdsman integration install omp
herdsman integration install claude
herdsman integration install codex
herdsman integration install opencode
herdsman integration install hermes
herdsman integration install qodercli
```

## Uninstall integrations

```bash
herdsman integration uninstall pi
herdsman integration uninstall omp
herdsman integration uninstall claude
herdsman integration uninstall codex
herdsman integration uninstall opencode
herdsman integration uninstall hermes
herdsman integration uninstall qodercli
```

## How Herdsman uses integrations

Herdsman combines three signals:

| Signal | Purpose |
| --- | --- |
| Process detection | Identifies which pane owns which running process. |
| Agent integration events | Reports semantic state such as `working` or `blocked`. |
| Screen heuristics | Fills gaps when hooks are unavailable or incomplete. |

Integrations enrich state reporting. They do not replace process detection.

Some integrations also report native agent session references. If `[session] resume_agents_on_restore = true` is enabled, Herdsman uses official session references to resume Claude Code, Codex, Pi, Hermes Agent, and OpenCode panes after a Herdsman server restart.

Native session restore requires current Herdsman integrations: Pi integration version `2`, Claude Code version `4`, Codex version `4`, OpenCode version `2`, or Hermes Agent version `2`. OMP integration version `2` reports agent state only. Check installed versions with `herdsman integration status`.

## Pi

Install the Pi integration:

```bash
herdsman integration install pi
```

Herdsman writes the bundled extension to:

```text
~/.pi/agent/extensions/herdsman-agent-state.ts
```

If `PI_CODING_AGENT_DIR` is set, Herdsman writes to `$PI_CODING_AGENT_DIR/extensions/herdsman-agent-state.ts` instead. The extensions directory must already exist. Uninstall removes only that extension file.

## OMP

Install the OMP integration:

```bash
herdsman integration install omp
```

Herdsman writes the bundled extension to:

```text
~/.omp/agent/extensions/herdsman-omp-agent-state.ts
```

If `PI_CODING_AGENT_DIR` is set, Herdsman writes to `$PI_CODING_AGENT_DIR/extensions/herdsman-omp-agent-state.ts` instead. The extensions directory must already exist. Uninstall removes only that extension file.

The OMP integration reports `omp` as the agent label through Herdsman's socket API. It does not require native process detection for the `omp` executable.

## Claude Code

Install the Claude Code hook:

```bash
herdsman integration install claude
```

The hook reports agent state to the local Herdsman socket when Claude Code exposes hook events.

Herdsman uses `~/.claude` by default, or `CLAUDE_CONFIG_DIR` when set. The Claude config directory must already exist. Install writes `hooks/herdsman-agent-state.sh` and updates `settings.json` with Herdsman hook entries. Uninstall removes the matching hook entries and deletes the hook script.

## Codex

Install the Codex hook:

```bash
herdsman integration install codex
```

Codex state is reported through the same local socket API used by other integrations.

Herdsman uses `~/.codex` by default, or `CODEX_HOME` when set. The Codex config directory must already exist. Install writes `herdsman-agent-state.sh`, updates `hooks.json`, and ensures `[features] hooks = true` in `config.toml`. It also removes the deprecated top-level `codex_hooks` flag when present. Uninstall removes Herdsman entries from `hooks.json` and deletes the hook script, but leaves `config.toml` unchanged.

## OpenCode

Install the OpenCode plugin:

```bash
herdsman integration install opencode
```

Herdsman writes the plugin to `~/.config/opencode/plugins/herdsman-agent-state.js`. The OpenCode config directory must already exist. Uninstall removes only that plugin file.

The plugin reports semantic state while OpenCode runs inside a Herdsman pane. After OpenCode emits a session-bearing event, Herdsman can use the reported session id to resume the pane with `opencode --session <id>`.

## Hermes Agent

Install the Hermes Agent plugin:

```bash
herdsman integration install hermes
```

Herdsman writes `~/.hermes/plugins/herdsman-agent-state/` and enables `herdsman-agent-state` in `~/.hermes/config.yaml`. The Hermes config directory must already exist. Restart Hermes after installing so the plugin loads. Uninstall removes the plugin directory and removes `herdsman-agent-state` from `plugins.enabled`.

The plugin reports lifecycle, tool, approval state, and session id while Hermes runs inside a Herdsman pane. Herdsman can use the reported session id to resume the pane with `hermes --resume <id>`. Native screen heuristics remain available when the plugin is not installed.

## Qoder CLI

Install the Qoder CLI hook:

```bash
herdsman integration install qodercli
```

The hook reports semantic state to Herdsman when Qoder CLI emits lifecycle events.

Herdsman uses `~/.qoder` by default, or `QODER_CONFIG_DIR` when set. The Qoder config directory must already exist. Install writes `hooks/herdsman-agent-state.sh` and updates `settings.json` with Herdsman hook entries. Uninstall removes the matching hook entries and deletes the hook script.

Native screen heuristics remain available when the hook is not installed.

## Custom status labels

Integrations can report a short visual label without changing the semantic state.

For example, an agent can remain semantically `working` while showing `indexing` in the UI.

```bash
herdsman pane report-agent 1-1 \
  --source custom:docs \
  --agent docs-bot \
  --state working \
  --custom-status indexing
```

User hooks that run next to a Herdsman-managed integration should use metadata instead of `report-agent`. Metadata changes presentation without taking over the integration's `idle`, `working`, `blocked`, or session restore authority. `--agent` guards the report so it only applies while that authoritative agent is active. `--applies-to-source` guards the report so it only applies while that lifecycle authority source is active. `--display-agent` changes the visible name.

```bash
herdsman pane report-metadata "$HERDSMAN_PANE_ID" \
  --source user:claude-title \
  --agent claude \
  --applies-to-source herdsman:claude \
  --title "Refactor auth middleware" \
  --display-agent "Claude: auth" \
  --custom-status "refactor auth" \
  --state-label working="refactoring auth" \
  --ttl-ms 3600000
```

Custom status and state labels are visual-only. Waits, notifications, and workspace rollups still use the semantic state.

## Debug integration state

List known agents:

```bash
herdsman agent list
```

Read a pane when you need to verify what Herdsman can see:

```bash
herdsman pane read 1-1 --source recent --lines 50
```

If integration state looks wrong, first confirm the agent is running inside Herdsman and that the relevant hook or plugin was installed for the same user account.
