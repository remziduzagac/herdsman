---
title: Session state and restore
description: Understand what Herdsman keeps live, restores after restart, replays from history, resumes through agent integrations, and hands off during updates.
---

Herdsman has several state paths. They solve different problems.

## Live persistence

Normal detach keeps the Herdsman server running. Panes, shells, agents, servers, tests, and command processes keep running inside that server.

Detach the client with `ctrl+b q`. Reattach later:

```bash
herdsman
```

This is the strongest persistence path because the original processes never stop.

## Snapshot restore

If the Herdsman server stops and starts again, the original pane processes are gone. Herdsman restores the saved session shape: workspaces, tabs, panes, cwd, layout, and focus.

Snapshot restore does not preserve running shells, servers, tests, or arbitrary processes. Panes that cannot use a stronger restore path come back as new shells in their saved directories.

## Pane screen history replay

Pane screen history restores recent terminal contents after a full server restart. It restores what Herdsman can show, not the old process.

This is off by default because pane output can include secrets, tokens, prompts, and command output. Enable it from Settings > Experiments > pane screen history or with:

```toml
[experimental]
pane_history = true
```

When enabled, Herdsman stores saved pane history in `session-history.json` next to `session.json`. Treat the Herdsman config/session directory like terminal history.

## Native agent session restore

Some agents can resume their own conversation sessions. Herdsman can use official integration-reported session references to restart supported agent panes after a Herdsman server restart.

Enable it with:

```toml
[session]
resume_agents_on_restore = true
```

When enabled, Herdsman only resumes panes that reported a native session reference through a current official Herdsman integration.

Native session restore requires these Herdsman integration versions or newer:

| Agent | Minimum Herdsman integration version | Resume command |
| --- | --- | --- |
| Pi | `2` | `pi --session <path-or-id>` |
| Claude Code | `4` | `claude --resume <id>` |
| Codex | `4` | `codex resume <id>` |
| OpenCode | `2` | `opencode --session <id>` |
| Hermes Agent | `2` | `hermes --resume <id>` |

OMP integration version `2` reports agent state, but does not report native session references for restore.

Run `herdsman integration status` to check installed integration versions. Reinstall outdated integrations with `herdsman integration install <agent>`.

Unsupported, missing, invalid, duplicated, or stale session references restore as normal shells in the saved pane directory.

If native agent session restore applies to a pane, Herdsman resumes the agent session instead of replaying saved pane history for that pane.

## Live handoff

Live handoff is for update and remote attach flows that need to replace a running Herdsman server. It asks the old server to transfer live panes to the new server, so pane processes can keep running across the server replacement.

This is different from snapshot restore, pane history replay, and native agent session restore. Handoff tries to keep the current processes alive. The others reconstruct state after the old server has already stopped.

Live handoff is experimental and opt-in:

```bash
herdsman update --handoff
herdsman --remote workbox --handoff
```

Plain `herdsman update` and plain `herdsman --remote workbox` use the normal restart/stop flow by default.

`herdsman update --handoff` only applies to installs managed by Herdsman's own updater. Homebrew and Nix installs are updated through their package managers, so `herdsman update` is disabled there and cannot perform live handoff.

## What Survives

| Case | Processes keep running | Layout returns | Recent screen returns | Agent conversation resumes |
| --- | --- | --- | --- | --- |
| Detach and reattach | Yes | Yes | Yes, from the live terminal | Yes, because the process never stopped |
| Server restart | No | Yes | Only with pane screen history | Only with native agent session restore |
| Update without `--handoff` | Compatible servers keep running; restart-required servers may need stop/restart | Yes after restart | Only with pane screen history | Only with native agent session restore |
| Update with `--handoff` | Best effort for supported running servers | Yes | Yes, from the live terminal if handoff succeeds | Yes, because the process keeps running if handoff succeeds |
