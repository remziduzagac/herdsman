Herdsman はペインをバックグラウンドサーバーで動かし続けます。ターミナルクライアントはデタッチして、あとで再接続できます。

ローカル、SSH、`herdsman --remote` の各ワークフローについては [Herdsman での作業の進め方](/ja/docs/how-to-work/)を参照してください。

## デタッチと再アタッチ

`ctrl+b q` でクライアントをデタッチします。ペインとエージェントは動き続けます。再度 `herdsman` を実行すると再アタッチします。セッションとそのペインを停止するには `herdsman server stop` を使います。

サーバーの完全停止後に Herdsman が再起動すると、保存されたセッションの形を復元します。デタッチ、サーバー再起動、画面履歴リプレイ、エージェントネイティブのセッション復元、ライブハンドオフでそれぞれ何が生き残るかは[セッション状態と復元](/ja/docs/session-state/)を参照してください。

## 名前付きセッション

独立した Herdsman サーバーが欲しいときは名前付きセッションを使います。

```bash
herdsman session list
herdsman session attach work
herdsman session attach side-project
herdsman session stop work
herdsman session delete side-project
```

名前付きセッションは独自のペイン、タブ、ワークスペース、ソケット、ランタイム状態を持ちます。グローバル設定ファイルは共有されます。

スクリプトでは `--json` を使ってください:

```bash
herdsman session list --json
herdsman session stop work --json
herdsman session delete side-project --json
```

## SSH 越しのリモートアタッチ

リモートモードは 2 つあり、[Herdsman での作業の進め方](/ja/docs/how-to-work/)で比較しています。tmux スタイルの方法では、サーバーに SSH してそこで `herdsman` を実行します。もうひとつは、ローカルマシンから SSH 越しにアタッチする方法です:

```bash
herdsman --remote workbox
herdsman --remote ssh://you@server:2222
```

このモードでは、ローカルの Herdsman はシンクライアントです。SSH 越しに接続し、リモートの Herdsman サーバーを起動またはアタッチして、UI をローカルターミナルにストリーミングします。クライアントがローカルで動くため、Herdsman は画像クリップボードの貼り付けのようなローカルデスクトップ機能をリモートセッションにブリッジできます。画像をリモートの一時ファイルにコピーし、そのパスを貼り付けます。

デフォルトでは、`herdsman --remote` はそのアタッチにローカルの Herdsman キーバインドを使います。リモートサーバーの設定が異なっていても、ローカルの操作感覚を維持できます。ローカルキーバインドはアタッチ時のスナップショットなので、ローカルのキーバインドを編集したらデタッチして再アタッチしてください。リモートサーバーの設定を使いたい場合は `--remote-keybindings server` を使います。ローカルのカスタムコマンドキーバインドは送信されません。それらのコマンドはリモートホスト上で実行されてしまうからです。

繰り返し接続する相手は SSH config を使ってください:

```text
Host workbox
  HostName server.example.com
  User you
  Port 2222
```

その後はこれでアタッチできます:

```bash
herdsman --remote workbox
```

リモートアタッチは x86_64 と aarch64 の Linux および macOS ホストをサポートします。Herdsman はリモートのプラットフォームを確認し、リモートの `PATH` 上にある一致する `herdsman` を優先し、次に `~/.local/bin/herdsman` を確認します。一致するバイナリがない場合、対話的な実行では `~/.local/bin/herdsman` へのインストールを提案します。非対話的な実行はホストを変更せずに失敗します。`~/.local/bin` がリモートの `PATH` にない場合、Herdsman はインストール後に警告します。

ネイティブ Windows の `herdsman --remote` は Windows ベータの範囲外です。Windows からはサーバーに SSH してそこで `herdsman` を実行してください。

デフォルトでは、`herdsman --remote` はあなたの SSH config を最初に include し、その後にフォールバックのキープアライブ設定を加えた一時的な SSH config を通してブリッジを実行します。既存のユーザーのキープアライブ設定が優先されます。Herdsman が生成するブリッジ設定を使わず素の `ssh` を使うには `[remote].manage_ssh_config = false` を設定してください。

デフォルトでは、実行中のリモートサーバーの置き換えや再起動が必要な場合、リモートアタッチは通常の再起動/停止フローを使います。対応する実行中リモートサーバーで実験的なライブハンドオフにオプトインするには `--handoff` を渡します:

```bash
herdsman --remote workbox --handoff
```

先にサーバーへ SSH してそこで `herdsman` を実行した場合、Herdsman は完全にサーバー上で動きます。このモードは便利でシンプルですが、通常のターミナルテキスト貼り付けを超えてローカルデスクトップのクリップボードにはアクセスできません。

ローカルとリモートのプラットフォームが一致する場合、直接インストールでは Herdsman は現在のローカルバイナリをコピーできます。Homebrew、mise、Nix のインストールの場合、またはプラットフォームが異なる場合は、`https://herdsman.invalid/latest.json` から現在のクライアントバージョンに一致するリリースアセットをダウンロードします。

ローカルビルドやカスタムバイナリの場合は、リモートアタッチの前に `HERDSMAN_REMOTE_BINARY` にローカルファイルパスを設定してください。

```bash
HERDSMAN_REMOTE_BINARY=target/release/herdsman herdsman --remote workbox
```

## リモートの名前付きセッション

リモートホスト上の名前付きセッションにアタッチするには、`--remote` と一緒に `--session` を使います:

```bash
herdsman --remote workbox --session agents
```

## ダイレクトターミナルアタッチ

完全な Herdsman アタッチはワークスペース UI 全体を開きます。ダイレクトアタッチは、サーバーが所有するターミナルをひとつだけ、現在のターミナルに開きます。

ダイレクトターミナルアタッチは Windows ベータでは Unix 専用です。

エージェントターゲットでアタッチ:

```bash
herdsman agent attach reviewer
```

ターミナル ID でアタッチ:

```bash
herdsman terminal attach term_abc123
```

ダイレクトアタッチは、現在レンダリングされているターミナル状態をストリーミングし、その後ライブの ANSI フレームを流します。入力はそのターミナルに直接送られます。

`ctrl+b q` でデタッチします。リテラルの `ctrl+b` は `ctrl+b ctrl+b` で送ります。

ひとつのターミナルの入力とリサイズを所有できる書き込み可能なダイレクトアタッチクライアントはひとつだけです。既存の所有者を置き換えるには `--takeover` を使います:

```bash
herdsman terminal attach term_abc123 --takeover
```

## シングルプロセスの逃げ道

バックグラウンドのサーバー/クライアント分離なしで Herdsman を実行するには `--no-session` を使います:

```bash
herdsman --no-session
```

これは主にデバッグや互換性のための逃げ道です。デフォルトの永続セッションモードが通常の使い方です。
